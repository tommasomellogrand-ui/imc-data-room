2. ROOT CAUSE ESATTA

team() in 001-18 cercava soltanto MENU_clubOverviewDraw sul nodo squadra.
Nel DOM NATIONS tutte le 64 side delle 32 fixture espongono invece
MENU_association_draw sul proprio homeTeam/awayTeam.

La regex club non corrisponde: id=null, controlled=false, status
UNRESOLVED_TEAM_ID. resultRows() emette poi il warning.
L'identificativo esiste nel DOM: non è un dato mancante né una failure
di mapping successiva.

Non è presente nell'importer una lookup/mappatura successiva che rifiuti
gli ID 646xxx. resultRows trasferisce team.id nei campi già esistenti
home_sm_club_id/away_sm_club_id e calcola il fingerprint.
Non è necessaria alcuna nuova tabella o modifica Gateway per correggere
questo punto del parser. Non è stata verificata con WRITE una eventuale
validazione server-side: il CASE non la autorizza.

3. MARKUP E NAMESPACE

NAZIONALI:

Sono identificativi dell'entità association/nazionale che Soccer

affermato che siano ID globali stabili attraverso tutti i Game World.

6. FINGERPRINT E DATI GIÀ PRESENTI

Algoritmo hash, lista campi e classificazione idempotenza NON modificati.
Il valore fingerprint può legittimamente cambiare perché un team ID
prima null è ora valorizzato: cambiano i dati in ingresso, non l'algoritmo.

NON effettuare reset.
Retest sulle righe già presenti con preload normale:
- righe già corrette/invariate -> IDENTICAL;
- stesso fixture ID con vecchi national ID null -> CHANGED_EXISTING;
- nuovi dati -> NEW;
- fingerprint duplicato su altro ID -> DUPLICATE_CONTENT.

CHANGED_EXISTING resta senza update automatico. Quindi le righe storiche
non vengono bonificate da questa patch. Un warning storico non scompare
dal DB per il solo rilancio; la risoluzione corrente può essere corretta
mentre lo storico resta da trattare con un CASE distinto.
