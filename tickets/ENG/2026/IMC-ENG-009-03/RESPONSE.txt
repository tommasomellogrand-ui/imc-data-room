1. EXECUTIVE VERDICT

L'architettura approvata in IMC-ENG-009-02 e IMC-CREATIVE-001-02 è pronta per essere trasformata in una sequenza di CASE operativi piccoli e reversibili.

Il repository reale conferma che la migrazione deve essere estrattiva e progressiva, non una riscrittura. Oggi:
- minisite/GW001..GW009 esistono come package fisici autonomi;
- GW001 contiene app.js, exploration.js/css/data/assets e pagine route-specifiche;
- GW007 contiene app.js, data.js, theme/assets e pagine route-specifiche inclusi kingdom.html e map.html;
- site-assets/gameworld/app-core.js è un vecchio renderer condiviso che contiene direttamente mapping GW001..GW009 e nove shell visuali, quindi NON può diventare il nuovo Universal Core;
- alcuni minisiti/workflow storicamente hanno referenziato /minisite/shared/app-core.js, creando una source-of-truth da chiarire durante la migrazione;
- il comportamento di valore è oggi distribuito nei singoli app.js/exploration.js e va estratto dietro l'output esistente.

Blueprint definitivo:

ONE UNIVERSAL CORE
→ FAMILY CONTRACT LAYER
   → SINGLE
   → MULTI_GOLD
→ SEMANTIC CONTRACT / VIEW-MODEL LAYER
→ GW CREATIVE PACKAGE
→ OPTIONAL FEATURES + SIGNATURE RENDERERS

Regola di esecuzione:
NON MIGRARE PRIMA L'INTERFACCIA.
MIGRARE PRIMA I CONTRATTI E IL COMPORTAMENTO DIETRO L'INTERFACCIA.

GW001 e GW007 sono acceptance tests del Core, non template da ricostruire.

Primary destination semantics:
- Home;
- Competitions;
- Results;
- Schedule;
- Standings;
- More/secondary access a entities/features.

Competition-first context:
WORLD → COMPETITION → optional DIVISION/STAGE → DETAIL.

Contract requirements:
- Results/Schedule items devono poter produrre match deep link;
- Match è first-class semantic object;
- Competition hub espone capability disponibili;
- Hub→Detail conserva origin/context quando valido;
- browser back rispetta history nativa, non ricostruzioni arbitrarie;
- URL contiene state necessario al deep link;
- division/competition context persiste soltanto su route compatibili;
- context incompatibile viene validato/reset deterministicamente;
- mobile espone sempre Home/Results/Schedule/Standings + full menu access;
- rendering navigation è GW-owned entro placement/behavior family.

world/context-index

optional division-detail

Context hierarchy standard:
WORLD → COUNTRY → DIVISION/COMPETITION → DETAIL.

GW007 hierarchy:
WORLD → TERRITORY/KINGDOM → DIVISION/COMPETITION → DETAIL.

Primary context entry contract:
- maxPrimary = 4;
- provider required;
- primary e secondary entries fanno parte dello stesso complete context set;
- context selector completo sempre disponibile;
- active context serializzato in URL;
- context switch mantiene route corrente quando semanticamente compatibile, altrimenti usa family fallback route dichiarata;
- Results/Schedule/Standings/Clubs/Managers/Players/Transfers possono ricevere context filter;
- mobile context selector sempre raggiungibile dalla family navigation area.
